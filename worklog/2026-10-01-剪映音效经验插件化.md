# 把剪映接入和音效经验做成一个插件

## 做了什么

把现有 MCP、单轨音效整理能力和两轮真实剪辑的经验，整合成了「剪映音效助手」插件。插件沿用 jianying-mcp 这个名字，里面有本地 MCP 启动配置和一个音效编排技能。

技能告诉后续助手怎样读取用户当前认可的工程版本、选择缓存素材、按字幕安排时间点、保留旧音效的调整，以及把多个片段收进一条轨道。比较细的声音经验放在 MCP 的指南工具里按需读取：章节转场、操作反馈、完成提示和重点强调，对应四类已经实践过的内置音效预设。独立 MCP 和 CLI 也能读取同一份经验。

补了安装脚本和插件源清单，在本机通过 Codex CLI 完成安装和启用。用安装到缓存里的真实插件配置测试了 MCP 握手、工程列表和指南查询，随后移除指向同一运行环境的重复独立 MCP 配置；修改前的配置已经备份。安装期间没有编辑剪映工程。

自动测试增加到 54 项，新增不同工作目录、中文配置路径、运行环境缺失或移动时的报错，以及 Windows PowerShell 5.1 解析检查。技能格式校验、本地测试、PowerShell 5.1 下重复安装和真实 MCP 调用都通过了。

## 为什么做

工具知道怎么写草稿，不等于后续助手知道该在什么地方放声音、放多少、如何保持时间线好整理。用户希望把这次认可的效果变成可复用能力，所以插件同时打包执行工具和编辑判断经验。

经验也不能变成死规定。一次约 14 分钟的演示从 19 处增加到 47 处后得到认可，可以作为口播录屏的密度参考，但不能要求所有视频都加同样数量，也不能把这次素材的音量硬套给任何新音频。

## 值得记住的决策和坑

插件安装会把文件复制进 Codex 缓存，不能假设客户端工作目录就是插件目录。这里把本机 Python、入口和配置的绝对路径放进用户本地运行指针，启动器只读取这个指针；缓存搬位置、聊天换目录都能启动。真实运行环境和素材不打包进插件，公开文件里也不需要出现用户路径。

采用本机 Codex 已支持的兼容插件清单，通过 CLI 登记插件源和安装，没有伪造远程 app ID，也没有把本地进程包装成网页版接口。用户重启 Codex、开新聊天以后，插件技能和 MCP 才能进入新的上下文。

独立 MCP 和插件 MCP 同时启用会重复加载相同工具，增加无用上下文。安装脚本只在插件握手成功后，移除命令和入口都指向本项目的那条旧连接，其他 MCP 不动。需要并存时也能显式保留。

Windows 自带 PowerShell 5.1 会把没有 BOM 的中文 UTF-8 脚本当作本机 ANSI 编码读取，甚至导致引号解析失败。给三个 PowerShell 脚本补了 UTF-8 BOM，并用实际 5.1 解析器验证，再实测了重复安装。

技能保持短而明确，音效指南按需加载；指南工具、CLI 和插件引用同一份数据，避免三套经验各自过时。已有授权和退出答复继续有效，不要求用户每一步重复确认；只有实际运行中的剪映阻止首页登记时，才需要保存退出。

## 一句话亮点

把一次剪辑里积累的好声音和好习惯，装进一个能直接接入剪映、继续手动调整的插件。
