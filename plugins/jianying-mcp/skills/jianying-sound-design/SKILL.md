# 剪映音效编排

通过本插件的本地 MCP 编辑工程副本。音效作为独立可编辑片段放在一条轨道上；用户已有的时间、音量和淡入淡出调整应保留。优先使用用户本机已缓存的剪映内置音效，按用户风格偏好选择素材。

## 读取与编排

- 用 `jianying_doctor` 检查环境，`list_jianying_drafts` / `inspect_jianying_draft` 确定用户当前认可的工程版本。继续编辑时使用最近保存的副本，不退回最初工程重建已认可的声音。
- 用 `get_jianying_sound_design_guide` 按需读取密度、音量、静音截取和四类素材预设。其数量与音量是口播录屏的起点，不能替代用户风格或试听反馈。
- 分页读取需要的字幕与片段时间，选模块切换、实际操作、完成反馈和重要信息作为锚点。用户授权“合适位置加一些”时可自行安排，说明位置根据字幕推断。字幕中的“点击”不等于画面点击的精确帧。
- 用 `find_jianying_cached_sound_effects` 查实际本地文件，再把路径放进计划。预设里的 role、search_title、anchor_offset_seconds 是编排元数据，不要直接作为 effects 字段传入。
- 保持人声清楚。先检查音频的有效发声区间，再设置截取范围、低音量及短淡入淡出。预设的截取值只适用于对应素材，其他音频应重新确认。

## 单轨与保留

`prepare_sound_effects` 默认 `track_mode="single"`，每个音效仍是独立片段。新增片段与已有音效不重叠，避免擅自移动、截短用户已调整的声音。确需叠加时可采用 `independent`，解释原因。

继续追加音效或整理旧轨道时，从 inspect 明确选择音效轨道 ID，传 `consolidate_track_ids`，把旧片段和新片段收进同一轨。不要自动把所有 audio 轨道合并，配音和背景音乐可能也是 audio。只合轨时可用 `effects=[]`。轨道静音、锁定等设置不同会被工具拒绝，先确定怎样保留用户的播放状态。

## 生成与登记

用 prepare → build → verify 生成并检查新副本。工具保留原片段、字幕、材料、时长和未知字段，原工程不覆盖。同名副本已存在时选择新名字；验证失败时处理明确原因，不要绕过校验写首页索引。

publish 需要剪映已保存并正常退出。已有退出答复且 doctor 确认未运行时直接继续，不要重复询问。剪映仍在运行时，先完成不受影响的准备和副本工作，再请用户保存退出；源工程保存后若改变，重新 prepare / build。不要自动关闭剪映。

剪映重新保存会整理默认字段、改用工程路径占位符、按视频帧对齐时间。verify 校验的是生成快照；继续编辑保存后的副本时，把它作为新源准备下一轮，不能用旧完整哈希判断它损坏。

交付说明新工程名称、总音效数、新增数与轨道数，并告诉用户可逐片段试听和调整。只有实际完成的打开、试听或保存检查才能报告为已验收。

## 连接问题

MCP 连接缺失、运行目录移动或首次安装时，读 [references/connection.md](references/connection.md)。只需要声音润色时不要自动部署远程服务、导出视频或上传用户素材。
