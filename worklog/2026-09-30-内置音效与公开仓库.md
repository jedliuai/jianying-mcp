# 给工程加上内置音效，把接入代码公开

## 做了什么

给接入项目增加了按名称查找剪映缓存音效的能力，CLI 和 MCP 都能使用。读取剪映已经下载到本机的音频，与本地资源目录中的名称、资源 ID、素材哈希对应起来，不需要操作界面或额外购买素材包。

用户授权我自己挑选位置之后，结合字幕里的模块切换、操作反馈和系统亮点，为一个 14 分钟左右的演示工程安排了 19 处音效。用了四类已缓存内置音效：转场、轻巧提示、完成提示、弹出声。音量控制在 8% 到 10%，并处理了素材开头静音、截取范围、淡入淡出。

音效版完整工程已生成并登记到剪映首页，原视频、字幕、337 个片段和时长保留。每个音效都是独立轨道，后续删改方便。登记发生在用户保存并退出剪映之后，原草稿没有覆盖，首页索引也留下了备份。最终播放、保存重开需要在剪映里检查。

已在 GitHub 创建并公开 jedliuai/jianying-mcp，上传接入代码、测试、通用说明和工作总结。个人草稿、字幕全文、缓存音效、资源数据库、配置和备份全部排除，公开说明里也移除了实际工程名称。自动测试增加到 38 项，补充了 Windows GitHub Actions。

## 为什么做

用户希望尽量直接用剪映自带的音效，并且已有会员，同时不想手动告诉我每一个时间点。所以这一步把“现有素材能用”和“助手可以根据内容安排编辑”连了起来；再把代码公开，后面接入其他工程或电脑更方便。

## 值得记住的决策和坑

剪映资源数据库的 effect 和 music 表可能都是空的，真正的目录记录还存在 http_cache 的响应体里。查询必须用 SQLite 只读模式，解析 JSON 后只提取名称、资源 ID、哈希和已存在的本地音频，绝不能把签名 URL 或整份资源响应带进公开仓库。

64 位资源 ID 要用字符串保留，不能让 JavaScript 浮点数损失精度。数据库目录也不能只认一个账号子目录。素材文件存在还不够，先按目录哈希对应名字，再测真实音频时长和有效发声范围，这样不会把音效头部的静音一起对齐到字幕锚点。

这次按字幕来安排时间，没有逐帧确认鼠标点击。章节转场和强调提示比较适合这种方式，两个操作反馈位置则可能还需要在剪映里轻微挪动。音效不要铺得太密，也不要为了展示库里有什么就放夸张的搞笑音效，口播演示首先要听得清楚。

FFmpeg 的输出在 Windows 上应明确按 UTF-8 读取；默认 GBK 遇到中文素材信息会导致子进程读取线程报错。GitHub Actions 的标签有些指向带注释的 tag 对象，固定提交时需要先解引用，不能把 tag 对象本身的 SHA 当成执行代码提交。

会员的内置素材用于本机工程，与把素材公开分发是两件事。代码仓库只分享工具实现和合成测试数据，真实素材留在本机。

## 一句话亮点

聊天一句话，就能把剪映内置音效放进合适的位置，每个声音仍是可以手动调整的独立轨道。
